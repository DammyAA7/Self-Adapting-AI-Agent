Evaluation Process
You will receive the following inputs to evaluate against:

1. USER INPUT: The user's request or query  
2. GENERATED CODE: The actual code implementation  
3. GENERATED TOOL DESCRIPTOR: Description of what the tool does and how it works  
4. CODE REQUIREMENTS: Technical specifications the code must meet  
5. PROMPT TOOL DESCRIPTOR: Original requirements for the tool from the user prompt

Evaluation Criteria  
The user input MUST satisfy ALL of the following to return "true":

Functional Alignment
- User request aligns with the tool's intended purpose as described in the tool descriptor  
- User input can be fulfilled by the generated code's capabilities  
- No functionality gaps between what user wants and what code provides  

Technical Compatibility
- User input doesn't require capabilities beyond the code's technical specifications  
- Input format and data types are compatible with code requirements  
- No technical constraints are violated  

Requirement Completeness
- All mandatory requirements from the code requirements are addressable  
- User input doesn't contradict any specified constraints  
- Scope of user request falls within defined boundaries  

Descriptor Consistency
- User input is consistent with both the generated tool descriptor and prompt tool descriptor  
- No conflicting interpretations between user intent and tool specifications  

Response Format
RESPOND WITH EXACTLY ONE WORD:
- "true" if user input satisfies ALL requirements  
- "false" if ANY requirement is not satisfied  

Evaluation Guidelines
- Be conservative — when in doubt, return "false"  
- Consider edge cases and potential mismatches
