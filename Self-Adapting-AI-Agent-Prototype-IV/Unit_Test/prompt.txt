## COMPLEMENTARY TESTING PHILOSOPHY

**Key Principle**: Since the function was developed through TDD, the original tests cover:
- Basic functionality and expected behavior
- Standard input/output scenarios
- Core business logic validation
- Primary error conditions

**YOUR FOCUS**: Test scenarios that are similar but different:
1. **VARIANT INPUT PATTERNS** - Similar inputs with subtle differences TDD wouldn't test
2. **ALTERNATIVE SUCCESS PATHS** - Different ways to achieve the same result
3. **SECONDARY FAILURE MODES** - Error conditions beyond primary TDD scenarios  
4. **EDGE BOUNDARY CONDITIONS** - Values just outside normal TDD test ranges
5. **IMPLICIT ASSUMPTIONS** - Testing assumptions TDD tests made but didn't verify
6. **ENVIRONMENTAL VARIATIONS** - Same operations under different conditions

## WHAT TDD TESTS vs WHAT YOU SHOULD TEST

### TDD Typically Tests:
- `add_todo("Buy milk")` → Success
- `complete_todo(1)` → Changes status to completed
- `delete_todo(999)` → Returns error for non-existent ID
- Basic CSV read/write functionality

### You Should Test (Similar but Different):
- `add_todo("")` → Empty string handling (TDD likely tested non-empty)
- `complete_todo(1)` when already completed → Double completion behavior
- `delete_todo("1")` → String ID vs integer ID handling
- CSV operations with different file states (locked, corrupted, missing)

## CRITICAL TESTING REQUIREMENTS

### Complementary Testing Rules
- **AVOID DUPLICATING TDD scenarios** - Don't test basic happy paths
- **TEST SIMILAR BUT DIFFERENT cases** - Variations of what TDD covered
- **VERIFY function availability before testing** - if a function is not available from the import, skip that test
- **CREATE TEMPORARY TEST FILES ONLY** - Each test must create its own temporary CSV file using the `path` parameter
- **NEVER modify todo.csv or any existing production files** - This is strictly prohibited
- **Focus on COMPLEMENTARY scenarios**:
  - Test BOUNDARY VARIATIONS (just outside TDD test ranges)
  - Test ALTERNATIVE INPUT FORMATS (similar data, different format)
  - Test SECONDARY ERROR CONDITIONS (errors TDD didn't specifically test)
  - Test ENVIRONMENTAL DIFFERENCES (same operation, different file states)
  - Test ASSUMPTION VIOLATIONS (break implicit assumptions TDD made)
  - Test SEQUENCE VARIATIONS (same operations in different orders)

### Complementary Todo Function Testing Focus Areas

#### 1. Input Variation Testing
- **Format Variations**: Same data in different formats (string vs int IDs, different date formats)

- **File State Variations**: Same operations on files in different conditions
- **Data State Variations**: Operations when data is in edge states
- **Timing Variations**: Same operations at different times/sequences

#### 3. Error Condition Variations
- **Alternative Error Paths**: Different ways the same operation can fail
- **Error Recovery Scenarios**: What happens after errors occur
- **Partial Error Conditions**: Some parts succeed, others fail
- **Cascading Error Effects**: How errors affect subsequent operations

#### 4. Environmental Variations
- **File System Variations**: Same operations under different file system conditions

def setUp(self):
    """Set up test fixtures for complementary scenarios."""
    self.test_dir = tempfile.mkdtemp()
    self.test_csv = os.path.join(self.test_dir, 'test_todos.csv')
    
    # Create CSV with proper headers
    with open(self.test_csv, 'w', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(['id', 'todo', 'status', 'priority', 'created_at', 'completed_at'])

def create_test_todo(self):
    """Create single test todo when add_todo not available"""
    with open(self.test_csv, 'w', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(['id', 'todo', 'status', 'priority', 'created_at', 'completed_at'])
        writer.writerow(['1', 'Test task', 'pending', 'medium', datetime.datetime.now().isoformat(), ''])

def create_completed_todo(self):
    """Create completed todo for testing different states"""
    with open(self.test_csv, 'w', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(['id', 'todo', 'status', 'priority', 'created_at', 'completed_at'])
        writer.writerow(['1', 'Completed task', 'completed', 'medium', datetime.datetime.now().isoformat(), datetime.datetime.now().isoformat()])

def create_malformed_csv(self, malformation_type):
    """Create various malformed CSV files for testing"""
    if malformation_type == 'missing_header':
        with open(self.test_csv, 'w', newline='') as f:
            writer = csv.writer(f)
            writer.writerow(['1', 'Test task', 'pending', 'medium', datetime.datetime.now().isoformat(), ''])
    elif malformation_type == 'wrong_columns':
        with open(self.test_csv, 'w', newline='') as f:
            writer = csv.writer(f)
            writer.writerow(['id', 'description', 'done'])  # Different columns
            writer.writerow(['1', 'Test task', 'false'])

def create_edge_case_data(self, edge_type):
    """Create data for edge case testing"""
    with open(self.test_csv, 'w', newline='') as f:
        writer = csv.writer(f)
        writer.writerow(['id', 'todo', 'status', 'priority', 'created_at', 'completed_at'])
        
        if edge_type == 'special_characters':
            writer.writerow(['1', 'Task with émojis 🎯 and spëcial chars', 'pending', 'high', datetime.datetime.now().isoformat(), ''])
        elif edge_type == 'long_text':
            long_text = "Very long task description " * 100
            writer.writerow(['1', long_text, 'pending', 'low', datetime.datetime.now().isoformat(), ''])
        elif edge_type == 'empty_fields':
            writer.writerow(['1', '', 'pending', '', datetime.datetime.now().isoformat(), ''])
